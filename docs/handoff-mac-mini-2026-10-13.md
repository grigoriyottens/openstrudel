## 3. Parakeet: закончить начатую реализацию

### Последнее решение пользователя — приоритетнее старых документов

Пользователь явно выбрал **Parakeet сейчас**, без усложнений. Одна встроенная мультиязычная модель; при первом нажатии микрофона предложить один раз скачать её; дальше локальная диктовка, автоматическое распознавание языка. Убрать выбор spoken language. Не требовать OpenRamble или приложение OpenAI. Не добавлять вторую модель, переключатель моделей или особую ветку для иврита.

Parakeet поддерживает английский, русский, французский и испанский, но не иврит. Это ограничение было прямо проговорено. Иврит интерфейса остаётся. Старое пожелание покрыть иврит диктовкой и старый документ с несколькими движками **отменены этим более поздним решением**. Пользователь не просил новый движок для Telegram или Linux — не расширяй замену composer-микрофона на другие каналы без необходимости.

## 4. Перенос сотрудника между устройствами

Пользователь явно вернул эту функцию в объём работ: нужно очень легко перенести сотрудника **из его настроек** и **drag-and-drop на секцию другого устройства в боковой панели**. Более раннее предложение убрать перенос больше не действует. В checkpoint новый UI переноса ещё не реализован.

Продуктовая модель:

- Нет главного устройства. Каждый сотрудник работает на конкретном устройстве; подключённые Mac/серверы равноправны в пользовательской модели.
- Настройки сотрудника показывают текущее устройство и понятное действие выбора другого доступного устройства.
- Drag-and-drop ведёт к тому же переносу, а не к другой реализации. Не предлагай недоступное/то же устройство как рабочее назначение.
- Перенести инструкции, идентичность, переписку, файлы, настройки и расписания. Объяснить, какие сервисы/аккаунты нужно подключить на новой машине.
- Показывать реальные этапы и результат. Не создавать двух одновременно работающих копий. Сбой связи или потерянный HTTP-ответ не означают, что можно удалить исходник.

Сначала изучи существующий `src/agent-move.ts` и `tests/agent-move.test.ts`:

- `LocalAgentMoves`: prepare/stage/release/activate/cancel/finish, блокировка сотрудника, архив, digest, идемпотентность, durable state, восстановление, контроль работающих заданий.
- `AgentMoves`: координатор старой топологии связанных Home; `/v1/agents/{id}/move`, `/v1/home/operations/{id}/retry`, внутренние `/v1/agent-transfer/*`.
- Он уже тестирует ряд опасных случаев; **это не доказательство работы между двумя независимыми Home, подключёнными через нынешний DeviceLibrary**. Сначала выясни этот архитектурный стык. Не возвращай пользователю понятие «главный Home» ради удобства реализации.
- `DeviceLibrary.swift`, `HomeClient.swift`, `Views.swift` содержат текущие маршруты устройств, назначения сотрудников и настройки.

Переиспользуй безопасный протокол, сделай минимальную связку для независимых устройств. Не передавай owner-токен одного устройства другому. Введи только действительно нужное durable восстановление и авторизацию. Покрой изменение сначала тестом, воспроизводящим реальный недостающий сценарий.

Проверка: два настоящих изолированных runtime, сотрудник с историей, файлом и расписанием; перенос туда и обратно из настроек и через drag-and-drop; недоступный источник/получатель, разрыв сети, restart, повторный запрос, активное поручение. После успеха сотрудник работает только на получателе, история и файл читаются, маршрутизация UI обновилась. Сначала тестовые сотрудники; не двигай рабочие чаты ради доказательства.

## 5. SSH-ключ: вставить, а не только выбрать файл

Пользователь хочет вставлять ключ как текст, без обязательного выбора файла. Правильная реализация всё равно использует **private key**: public key сам по себе не авторизует SSH. Простой альтернативный путь с паролем должен сохраниться.

Сейчас в `ConnectDeviceView.swift` → `OwnServerSetupView` есть адрес, root/login, Password / SSH key, file picker, passphrase и свёрнутый SSH port. В checkpoint это ещё не изменено.

Сделай небольшое понятное действие **Paste key** рядом с выбором файла; считывай clipboard только по явному нажатию. Понятный успех без показа секрета. Прими OpenSSH/поддерживаемый PEM private key, нормализуй окончания строк, ограничь размер. Для public key, пустого текста и неверного формата — короткая конкретная ошибка. Сохрани encrypted private key + passphrase. Не добавляй новые постоянные настройки, не логируй ключ, не передавай его в аргументах процесса и не сохраняй дольше setup session.

Переиспользуй `ServerAccess`, `SSHPrivateSession`, временный файл с правами 0600 и существующие SSH tests. Проверь настоящий вход с обычным и зашифрованным тестовым ключом и оба UI-пути: paste/file. Неправильный host key по-прежнему должен отклоняться.

Если причинное событие недоказуемо, так и скажи; добавляй только необходимую безопасную диагностику для повторения, без сбора содержимого переписки или секретов.

## 7. Простой заказ сервера по карте

Пользователь не удовлетворён «сначала зарегистрируйтесь в DigitalOcean». Ищет готовый сервис/интеграцию: понятный тариф, данные карты у платёжного провайдера, сервер создаётся, всё устанавливается и заканчивается рабочим сотрудником. Требуется фактически простой путь, а не кнопка, открывающая сложный сайт.

Ещё не выбрано и не реализовано. Изучи существующие:

- `docs/easy-cloud.md`, `docs/integrated-cloud-checkout.md`, `docs/wai-vds-native-integration.md`, `docs/server-setup-queue-2026-10-12.md`, `docs/ios-cloud-payments.md`.
- `WaiVDSContract.swift`, `WaiVDSClient.swift` и существующий DigitalOcean OAuth/quote/provisioning flow.
- Публичные `https://server.waiwai.is/api/v2/openstrudel/catalog`, `.../openapi.json` и `/api/v1/auth/options` — перепроверь фактический контракт и готовность. Ранее каталог был `live_gated`, `purchase_enabled: false`, `home_live_acceptance_pending`, с пустыми payable amounts. Не показывай работающую оплату до реальной готовности.

WAI VDS уже задуман как email/magic-link + hosted card checkout + provisioning через Kamatera. Возможно, это самый короткий путь, но пока это гипотеза. Если WAI продаёт/обслуживает хостинг, это **управляемая услуга/перепродажа**, а не просто «мы перекидываем платёж провайдеру». Прямо назвать продавца, цену и продление. OpenStrudel со своей стороны остаётся бесплатным.

Сравни готовые варианты по реальному onboarding: обязательная регистрация, платёж, KYC, возвращение в приложение, API provisioning, сроки, отмена, recurring cost и поддержка. Crypto-only сервис и card-to-crypto обменник не равны простому карточному VPS checkout. Не называй Vultr готовым решением: OAuth требует регистрации разработчика/разрешений провайдера; это ещё не путь «карта и сервер без аккаунта».

В интерфейсе: один ясный основной путь, отдельный «У меня уже есть сервер», короткая проверяемая цена и сведения о том, кто берёт плату. Не собирай raw card данные в OpenStrudel. Не меняй iOS companion/payment scope без отдельной проверки правил Apple. Для нового платного пилота нужен конкретный тариф/лимит; старое разрешение на уже удалённый Kamatera QA не является бессрочным разрешением на новые расходы.

## 8. Остальные пользовательские требования — сохранить и регрессировать

Это не заказ всё переписать повторно. Сверь уже готовые части с кодом/отчётами и тестируй затронутое:

- **Устройства:** авторизация на текущем устройстве, локальные и независимые удалённые сотрудники, создание на выбранном подключённом устройстве, ясный offline/reconnect; без «главного устройства» и обязательного «Личное / Работа».
- **Создание сотрудника:** задача прежде внешнего вида; образ в настройках; минимум обязательных решений.
- **Аккаунты:** переименование, совпадающий email разных workspace, несколько аккаунтов, понятный план/тип/workspace, быстрые данные, загрузка/ошибка вместо пустоты. Не выдумывать поля, которых OpenAI не возвращает.
- **Модели:** использовать рекомендацию конкретного аккаунта (`isDefault`/`defaultReasoningEffort`); fallback **`gpt-6.1-sol`, Medium**. Device default и per-employee overrides, без сброса явного выбора. Fast/Ultra Fast показывать только если реально объявлены аккаунту. Ранее real account рекламировал Fast, Ultra Fast проверялся синтетически.
- **Компьютер:** команды/файлы реально выполняются на устройстве сотрудника. Mac Computer Use был проверен настоящим Calculator → 391 и отдельным отказом доступа; не переносить права автоматически и не обещать GUI control на Linux/Windows без реализации.
- **Clipboard:** Command-V картинки, текст, изображения-файлы, вставка без дубликатов, сохранность черновика, правильное вложение и фактическое понимание в запросе. Предыдущая реализация есть; проверить регрессию после composer-правок.
- **Резервные копии/выход:** ясно, что и куда сохраняется, настоящий progress, отмена/ошибка, восстановление истории/файлов/расписаний; отсутствие видимого зависания. Не удалять данные ради теста.
- **Сервисы:** Google и Telegram — действия с видимым результатом, понятный получатель подключения, ошибки и retry. Свежая Google OAuth авторизация не была повторена в последних прогонах; не закрывать её старой сборкой. Тестовый bot token из старого чата не копировать в prompt/Git; использовать действующее безопасное хранилище и отдельный QA-бот.
- **WAI Core Team:** прежняя read-only проверка Mini показала работающую Telegram integration, одобренную group binding и обработку входящих сообщений. Часть сообщений штатно завершалась no-reply. Это не значит, что сотрудник сам пришлёт ответ на каждое сообщение. Не отправлять тестовые сообщения в рабочую группу без явной необходимости/разрешения.
- **Локализация:** English default, выбор RU/FR/ES/HE, все экраны, ошибки и RTL; аккуратный естественный язык. Минимум текста и отсутствие маркетингового слова AI в пользовательских текстах, когда это не требуется для честного согласия/объяснения передачи данных.
- **Иконка:** выбранная улыбающаяся булочка, согласованная в Dock, menu bar, iOS, web и release bundle. Не возвращать старую бесконечность; не создавать новые варианты. Проверять реальный установленный артефакт и cache.
- **Conversations:** Mac-верхняя кнопка уже удалена в main. Данные/история сохранены. iOS `ConversationBrowser` пока существует; не удалять историю как «лишний функционал». Если упрощаешь iOS-навигацию, отдельно проверить доступ к нужной истории.
- **Другие ОС:** текущий встроенный native engine сделан для Mac/iOS. Windows/Linux desktop диктовка не объявлена готовой; мобильная/настольная платформа и Home runtime — разные поверхности. Сохрани понятную архитектуру без преждевременного нового кроссплатформенного приложения.

## 10. Порядок продолжения и критерии завершения

1. Забрать checkpoint, сверить main, список задач и уже работающие другие ветки.
2. Закончить Parakeet и настоящие проверки Mac/iOS. Не выпускать только по успешному build.
3. Реализовать вставку SSH-ключа и безопасный перенос сотрудника через настройки/drag-and-drop, проверить на реальных изолированных runtime.
4. Довести расследование корпоративного аккаунта до доказанного вывода либо явно обозначить границу сохранившихся данных; исправить воспроизводимую проблему.
5. Найти и подтвердить простой card-checkout серверный путь, затем реализовать доступную интеграцию. Если внешняя коммерческая готовность/доступ блокируют оплату, назвать конкретную зависимость и подготовить всё независимое от неё, без фиктивной кнопки.
6. Пройти затронутые пользовательские пути, исправлять найденное и повторять соответствующие проверки. Сохранить screenshots/logs/receipts без секретов; обновить текущую очередь и release evidence.
7. Проверенное — commit, PR, merge main, выпуск и проверка доставки. Незавершённое не маскировать галочкой или успешной сборкой.

В процессе давай короткие сообщения о конкретном результате и следующей проверке. Не заставляй пользователя повторять решения из этого prompt. В конце кратко перечисли: **изменено / проверено на какой поверхности / реально опубликовано / осталось и почему**. Если запрашиваешь доступ или действие пользователя, объясни точную причину; параллельно продолжай независимую работу.
