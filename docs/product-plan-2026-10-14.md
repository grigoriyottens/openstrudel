# OpenStrudel — задачи по устройствам, iPhone и Telegram

Рабочий список по замечаниям Мика 14 октября 2026. Дополняет [план навигации и стабильности](navigation-stability-plan.md); прежние результаты остаются историческими. Новые пожелания собраны для планирования, без объявления прототипов готовыми функциями.

Принцип: сотрудник и его работа — в центре. Сервер — понятное место работы сотрудников. Обычные действия доступны рядом с объектом, технические подробности появляются только при необходимости.

**Решение пользователя:** у сотрудника одна общая лента обращений из приложения и Telegram, с отметкой исходного чата. Отдельные ленты по группам основным интерфейсом не становятся. Общая лента не объединяет аудитории, права и контекст разных групп.

## Задачи и порядок

Статусы ниже различают план, рабочий код, проверку и установленный результат. Галочка ставится только после проверки нужного пользовательского сценария.

На этом Mac локально установлен проверенный фикс восстановления настройки сервера; после перезапуска все три подключённых устройства видны онлайн, история открывается. Новая общая лента, общие имена, изменения списка и мобильные доработки ещё не выпущены. Ниже OS-01 остаётся открытым до общей поставки исправления, хотя локальная установка завершена.

### 1. Надёжное подключение — сначала

- [ ] **OS-13. Возврат из установки к пустому шагу без ошибки.** На `2.29.5.55` после Continue форма входа появляется снова. Воспроизвести в установленном приложении, устранить потерю состояния или скрытую ошибку. Повтор либо продолжает текущую установку, либо показывает конкретную причину и доступное действие. Проверить полный путь через интерфейс; не подменять его ручной установкой через SSH.
- [ ] **OS-14. Повторяющийся запрос Keychain.** На снимке запрос к `is.openstrudel.native` показывает процесс `security`. Установить вызывающий процесс, прекратить фоновые запросы и не читать рабочие ключи CLI для QA. Проверить запуск, переключение устройств и возврат из фона без системных диалогов; явное восстановление доступа остаётся действием пользователя.
- [ ] **OS-15. Общая работа над грантом WaiWai.** Прочитать актуальные сообщения нужной группы, настроить отдельный сервер через интерфейс OpenStrudel с SSH-ключом этого Mac, создать сотрудника «Грант WaiWai» с материалами проекта. Проверить создание, ответ, появление на другом клиенте и доступ команды. После работающего подключения отправить в группу короткую инструкцию со ссылкой на загрузку. Отдельный сервер заменяет первоначальный вариант с Mac mini; Мик подтвердил IP `2.29.5.55`.

- [ ] **OS-01. Установка и возвращение к ней целиком внутри приложения.** После временной потери сети продолжать проверку; при повторе сначала проверять уже запущенный сервер. Сохранять незавершённую установку и давать один понятный путь «Продолжить настройку». Завершённый сервер появляется в списке автоматически. Отдельно показывать готовность сервера и необходимость входа в аккаунт модели. Нужны проверки потери ответа установщика, обрыва во время проверки, закрытия приложения и возвращения, уже готового сервера, неверного ключа и отмены. Рабочее исправление прошло 48 нативных и 24 серверных/локализационных теста; продолжение сохранённой установки проверено настоящим интерфейсом отдельной QA-сборки. **Установлено на этом Mac**, проверено открытие истории и связь с тремя устройствами. Общая поставка исправления ещё не выполнена; доказательства — в [отчёте](releases/2026-10-14-server-setup-reconnect.md).
- [ ] **OS-02. Достоверное состояние связи.** Возвращение устройства онлайн должно обновлять список без ручного перезапуска. Запоздалый ответ старого запроса не может снова сделать доступный сервер офлайн. Неизменившийся список сотрудников не должен блокировать обновление связи. Проверить приложение на переднем плане и после возврата из фона, смену Wi‑Fi, сон/пробуждение Mini, перезапуск Home и туннеля. Временная потеря связи сохраняет сотрудников, историю и черновики. Рабочее исправление обновления состояния и регрессионные тесты есть; 52 теста соответствующих нативных наборов проходят. Длительная проверка на реальных устройствах ещё нужна. Сон Mini пока не подтверждён как причина; настройки питания автоматически не менять.

### 2. Имена и управление устройствами

- [ ] **OS-03. Понятные имена по умолчанию.** Для облачного узла — «Сервер», для Mac — понятное имя компьютера; контейнерные ID и UUID остаются внутренними. Имя назначается один раз и сохраняется на Home. Приглашение, список чатов, настройки и карточка сотрудника читают одно имя. Старые технические значения исправляются без замены выбранных пользователем имён. Несколько одинаково названных серверов различаются дополнительным адресом в настройках, без случайных суффиксов в основном имени. Проверка: новое подключение iPhone и уже подключённый Mac показывают одно имя; пересоздание контейнера его не меняет.
- [ ] **OS-04. Переименование сервера рядом с ним, с эффектом везде.** На Mac — «Переименовать» в меню заголовка и редактирование в строке; на iPhone — такое же действие в меню сервера и его карточке. Изменение записывается на Home и обновляется на остальных подключённых устройствах. Ошибка сохранения не выглядит успехом; пустое имя не принимается; отмена ничего не меняет. Имя не меняет адрес, идентификатор, ключи или принадлежность сотрудников. Проверка в обе стороны Mac → iPhone → Mac, после перезапуска и после возврата ранее отключённого клиента. Локальная подпись в UserDefaults из раннего прототипа этому требованию не соответствует и не является готовым решением.
- [ ] **OS-05. Переименование сотрудника на обеих платформах.** Сохранить единую карточку и существующий серверный путь изменения имени. Добавить легко обнаруживаемое действие рядом с сотрудником; не создавать ещё один редактор настроек. Сверить обновление имени в списке, заголовке, выборе сотрудника и настройках Telegram на Mac и iPhone. Переименование не создаёт нового сотрудника, не теряет историю и не меняет его образ или инструкции.
- [ ] **OS-06. Одинаковое добавление первого и следующего устройства.** В списке чатов понятное действие «Подключить устройство»; существующий «+» не должен означать исключительно создание сотрудника без возможности найти подключение. На iPhone один общий путь с двумя действиями: «Сканировать QR» и «Вставить ссылку». Повторно использовать существующий сканер и подтверждение приглашения. Проверить отказ в доступе к камере, неподдерживаемый сканер, неверный/истёкший QR, повторное подключение уже известного сервера, отмену и открытие ссылки из другой программы. Успех добавляет нужный сервер и его сотрудников, сохраняя текущий чат и черновик.
- [ ] **OS-07. Удобный длинный список.** Сворачивать сотрудников сервера до одного заголовка; запоминать свёрнутость локально. Поиск временно раскрывает совпадения, не стирая выбранное состояние. Сворачивание не закрывает уже открытый чат. Заголовок немного заметнее по размеру/насыщенности и отступам, с понятным раскрытием и состоянием связи; без дополнительных карточек и украшений. При перетаскивании к краю список плавно прокручивается в обе стороны, цель видна, отмена останавливает прокрутку. Проверить 30+ сотрудников, свёрнутую цель, недоступный сервер, Escape, узкое окно, крупный шрифт и VoiceOver. На iPhone тот же перенос доступен явным действием, без обязательного drag and drop. Есть рабочий прототип Mac; живую приёмку и проверку доступности ещё пройти.

### 3. Одна лента сотрудника и Telegram

- [ ] **OS-08. Общая лента с источником.** Показывать разговор в приложении, принятые обращения Telegram и ответы/результаты сотрудника. Отмечать источник и автора; обычный разговор участников группы не копировать в ленту. Сохранить настоящую связь запроса и ответа, доставку, файлы и обновления после возвращения устройства онлайн. Подробные правила ниже.
- [ ] **OS-09. Убрать лишний `Conversations` с iPhone.** После появления общей ленты убрать отдельный вход в переписки и дублирующие списки каналов. Существующая история остаётся доступной у своего сотрудника, импортированная история не удаляется. Для старой переписки без известного сотрудника сначала определить корректное место, а не скрывать её при удалении кнопки. Проверить ссылки, поиск, возврат из старого открытого экрана и пустую историю. Одна визуальная лента должна быть достаточна для обычной работы.

### 4. iPhone и диктовка

- [ ] **OS-10. Проверить равенство возможностей Mac и iPhone.** Пройти матрицу ниже на сопоставимых версиях Home и приложений, с одним и тем же сотрудником и правами. Отличать отсутствующую функцию от существующей, но плохо найденной. Исправлять конкретные расхождения; не копировать десктопную компоновку на маленький экран. Локальный запуск Mac и аппаратные возможности учитывать отдельно, с понятным объяснением реальных ограничений.
- [ ] **OS-11. Простая диктовка без обязательного выбора языка.** Сверить установленную iOS-сборку со свежим кодом: в нём автоматическое определение уже есть, а общий выбор Language относится к языку интерфейса. Один микрофон → речь → редактируемый текст; распознанное не отправляется само. Перед первым использованием кратко показать, что скачивается около 740 МБ для работы без сети. Затем не просить выбирать язык или повторно скачивать исправную модель. Проверить на физическом iPhone скорость, память, нагрев, русскую/английскую речь и переключение языков, отмену, пустую запись, нехватку места и прерванную загрузку. Ограничение иврита указать честно. Если качество или стоимость локального распознавания на телефоне окажутся неприемлемыми, сравнить с системной диктовкой на этих же записях; новый сервис или переключатель движков заранее не добавлять.

- [ ] **OS-12. Подготовить перенос в отдельных тестовых чатах.** Отдельная локальная задача: «Перенос трёх сотрудников на новый сервер OpenStrudel», ID `01a13a8a-3f72-7b91-82e0-0a565fb40c20`. Проверить исходные имена и систему, прочитать всю доступную историю с фиксацией пробелов, сопоставить инструкции, знания, характер, инструменты, доступы, расписания и Telegram-привязки. ## Правила общей ленты Telegram

Пример строки: **Telegram · WAI Core Team · Гриша** → текст обращения → связанный ответ сотрудника. Для сообщений из OpenStrudel — спокойная отметка «В приложении», когда она нужна для различения источников. Название чата ведёт к оригиналу там, где Telegram предоставляет действующую ссылку. При переименовании группы обновляется подпись, принадлежность сообщения определяется постоянным ID.

| Сценарий | Что видно и что происходит |
|---|---|
| Упоминание бота, команда ему или ответ на его сообщение | Если обращение разрешено правилами группы и принято в работу, оно появляется один раз; затем видны ход работы и ответ. |
| Обычная беседа в режиме ответов по обращению | Не появляется в ленте. Доступный боту контекст может использоваться по прежним правилам группы. |
| Сотрудник сам решает, требуется ли участие | Молчаливый отказ участвовать не превращает всю беседу в обращения. Прямое принятое поручение с ошибкой, отменой или ожиданием подтверждения остаётся видимым. Правила участия группы не меняются ради отображения. |
| Две группы пишут одновременно | Единая хронология с источниками; каждый ответ связан со своим запросом. Контекст, полномочия и адрес ответа остаются у исходной группы. Личные сведения из приложения не подмешиваются группе автоматически. |
| Пользователь пишет в обычное поле OpenStrudel | По умолчанию это разговор в приложении. Просмотр Telegram-сообщения сам по себе не включает публикацию в группу. |
| Пользователь выбирает ответ в Telegram | Явное действие у конкретного обращения, с видимым названием группы у поля и кнопки отправки; выход из режима возвращает локальный разговор. Черновики разных адресатов не смешиваются. |
| Сотрудник подготовил ответ, но Telegram недоступен | Различать «ответ готов» и подтверждённую доставку. Ошибка рядом с конкретным сообщением, с понятным действием. «Отправлено» не означает «прочитано». |
| Потеря подтверждения отправки | Не повторять автоматически сообщение, которое могло уже уйти. Отметить неопределённый результат; повторное нажатие не создаёт незаметных дублей. Использовать существующую очередь доставки. |
| Повторный update, перезапуск, несколько клиентов | Одно принятое обращение и один ответ, стабильный порядок, обновление статуса на Mac и iPhone. Подключение приложения не запускает второго получателя Telegram updates. |
| Голос, фото, документ, длинный ответ | Сохранять автора, подпись, вложения и связь ответа. Ошибка загрузки файла видима. Разбиение одного ответа на Telegram-сообщения не создаёт несколько независимых ответов в ленте. |
| Правка сообщения, отзыв доступа, смена сотрудника группы | Учесть только события, действительно доступные Bot API. Правка уже принятого запроса не запускает повторную работу молча. Отозванное подключение не продолжает отправку. Исторические ответы не приписываются новому сотруднику задним числом. |
| Темы Telegram и старая история | Сейчас темы отфильтровываются в обработчике. Не заявлять поддержку, пока адрес темы не проходит весь путь приёма и ответа. Старая импортированная история не повторно запускает задачи; доступные данные отделяются от обещания восстановить весь Telegram. |

Реализация начинается с уже существующих разговоров, признака `context_only`, идентификаторов Telegram и очереди доставки. Сервер отдаёт страницу общей ленты сотрудника с источником и состоянием доставки. Клиент не скачивает целиком все группы, чтобы склеить их самостоятельно. Обновление должно учитывать и исчезновение записи из видимой ленты после решения не участвовать, и позднее подтверждение доставки уже готового ответа.

Проверка — в изолированных тестовых чатах: адресованное сообщение, посторонняя беседа, ответ боту, два одновременных запроса из разных групп, вложение, ожидание подтверждения инструмента, отказ, ошибка модели, повтор update, перезапуск Home, потеря подтверждения Telegram и возвращение iPhone из фона. Для каждого сценария сверяются приложение, запись на сервере и фактически доставленный Telegram-ответ. Текущие рабочие группы для экспериментов не переключаются.
