# Build 43: AI providers, shared devices and the employee feed

Build 43 ships two merged pull requests:
- [#33](https://github.com/mikwiseman/openstrudel/pull/33) finishes the 14 October plan ([product plan](../product-plan-2026-10-14.md)). It covers server setup recovery, shared device names, colleague access and one employee feed with Telegram sources.
- [#34](https://github.com/mikwiseman/openstrudel/pull/34) adds the choice of an AI provider for each device and each employee ([design](../ai-providers.md)).

The release is cut from `main`. The build number is 43.

## What changed for users

- **AI providers.** Employees can run on a ChatGPT subscription or on an API key from OpenAI, Anthropic, xAI, Kimi, GLM, DeepSeek or OpenRouter. A key is checked before it is saved and is never shown again. The device has one model, and any employee can use a different one. Adding a second key never changes a model that was already chosen.
- **Colleagues.** «Пригласить коллегу…» creates a link that works for 24 hours and connects one device. The owner sees every connected device and can disconnect any device except the one in use, including a lost phone. The owner can also cancel a link that is still waiting.
- **Names.** Servers and employees can be renamed from the list, and the new name shows on every device. The app never shows container IDs or `.local` hostnames.
- **Employee feed.** App requests and accepted Telegram requests appear in one timeline, each with its source. Replies show their delivery state, and a failed delivery offers one action. The iPhone "Conversations" entry is gone once every connected Home runs build 43.
- **Server setup.** Setup continues on its own after a lost connection or a closed window, and a finished server appears in the list by itself.

## Verification

- **Tests on merged `main`:** TypeScript passes 474 tests with 1 skipped, and the typecheck is clean. The Mac app passes 297 unit tests in 32 suites. The iOS app and its UI tests compile.
- **Signed app:** the four packaged-app tests pass on the Developer ID signed bundle. They now also start the bundled Claude Code and check that it keeps its JIT entitlement. Without that entitlement, the Bun runtime silently falls back to a slow interpreter.
- **Reviews:** every branch went through adversarial review, and each confirmed finding was fixed with a test that failed first.
  - Server setup branch: 20 findings, two of them high severity.
  - Providers branch: 30 findings.
  - QA fixes: 9 findings.
- **Mac app (isolated QA bundle, separate Home, local mock providers):**
  - On a fresh install with no ChatGPT account, the user added an xAI key, and the real Codex engine answered.
  - Model selection by provider worked: an employee overridden to Grok answered while the device default ran on Claude through the real Claude Code CLI.
  - Removing a key and the colleague invitation API, including revoke and cancel, both worked.
- **Live Anthropic:** Mik pasted a test key into the isolated QA app himself. The model answered as Claude Fable 5.1. It wrote a file and ran a sandboxed command in its workspace, and the next turn remembered the result. The key was then removed and the QA data deleted, and Mik revokes the key.
- **iPhone simulator:** the provider-grouped model picker, the rewritten Telegram feed test, the queue, recovery, removing a device, pairing, largest text and remote employee creation all pass. One test, the approval-mode step of `testSettingsEmployeesMessagesAndRecovery`, depends on timing and also fails on the code before these changes.
- **Physical WaiPhone:** the candidate build was installed over the existing app. All real connections and «Грант WaiWai» were still there, with friendly names. The feed, Settings → Accounts, Devices and the model picker all opened.

## Known limits

- The real Homes keep showing the old "Conversations" entry and hide new features until each Home runs build 43.
- API keys for Kimi, GLM, DeepSeek and OpenRouter were verified only against a local mock. Anthropic was verified live.
- Claude routes support MCP services but not Codex skills or plugins.
- Subscription sign-in for Grok and Kimi Code is built on a separate branch and goes into build 44 after live sign-in tests.
