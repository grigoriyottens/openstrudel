# Build 49 — durable one-time reminders

Application/Home source: `de19fd0`. Published 17 October 2026.

## Behavior

- An employee can answer the current question and persist a one-time reminder
  through the existing scheduler. It no longer needs to wait inside a turn.
- The existing string-based tool contract also supports older Codex threads.
  Recurring schedules remain compatible; no database migration or extra loop.
- The clock wakes at the saved deadline. Persisted receipts prevent a second
  send after restart. Ambiguous delivery remains visible and is not auto-replayed.
- Native schedules distinguish completed, missed, failed and uncertain one-time
  results from paused recurring work. Task dates use the task's time zone.

## Storage

The tooling-only follow-up `f09fd0a` uses standard APFS copy-on-write clones for
ordinary rollback files. The SQLite backup API and integrity checks remain.
All fifteen storage safety checks pass, including changes to either copy,
unsupported volumes, storage errors and retention of active/foreign backups.
After healthy deployment, the normal two-backup policy removed one older managed
snapshot. Available space increased by about 3.4 GiB at that step and ended near
5.6 GiB. Physical memory pressure stayed normal; swap declined. No eligible native
cache was found. User files, release archives and Codex history were preserved.

## Remaining limits

- WaiClaw/CLO and Grant reject this Mini's existing SSH authentication. Their
  latest build, speech default and account status are not verified.
- The Android phone's outside-network Wolf route stalled in both the application
  and Android's platform HTTP client. TCP retransmissions are recorded, but the
  faulty network component is not identified. Local/USB success does not close it.
- There is no physical iPhone. Android and simulator results do not prove iOS
  microphone quality, system Camera behavior or the reported connection incident.
- The Android camera opens, but no real QR decode was performed. Its existing
  services screen is checked; new OAuth/MCP installation is separate acceptance.

These remain part of the overall goal. Build 49's release is verified; full
cross-device acceptance is not claimed. Private evidence is retained under

Android acceptance paths.
