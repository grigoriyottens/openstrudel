# OpenStrudel 1.0 (61)

Source: `8b6559af2972193804926f6152bd18d36b64f3e9` (PR #67, on top of PR #66).
Build 60 ran only on the three servers and on the release Mac; it was never
published, so this is the first public build since 59.

## Changes

Build 61 contains the fixes from the 19 October code review, checked again on
the current code, and the reserve models from build 60.

- Settings keep the person's choice. Choosing ElevenLabs or moving from an
  API-key model to a ChatGPT model no longer jumps back to the saved value.
- On iPhone, one tap in a device's settings row runs only the tapped control,
  so it can no longer cancel waiting invitations by accident.
- Ordinary network errors from a tool are no longer reported as exhausted
  resources, and they no longer discard a finished answer.
- The recovery watchdog no longer stops a turn while its own tool runs, for
  example while `connect_service` waits for a sign-in.
- One employee's outdated reasoning level no longer fails every chat on the
  account, and an unchanged SOUL is no longer injected again after a restart.
- Scheduled results stay out of paused or unlinked Telegram chats, and a
  recurring time inside the spring-forward hour now runs.
- A recording without speech no longer fails a request that has other
  content. A stalled Mac recognizer has a deadline again.
- A provider key cannot be replaced while a turn runs on it. Only the owner can
  send a schedule's results to another Telegram chat.
- Android offers only the send modes the Home accepts.
- README and architecture docs describe the current behavior.

- WaiWeb keeps only this build: the 59 DMG and Home package were removed and

- iOS 61 was uploaded once. Apple reports it VALID and ready for beta testing,
  and it is in the existing internal TestFlight group Mik. This is internal
  TestFlight, not an App Store or external beta release.

## Server patch 61-stt (same day)

Runtime source: `8ea678554ff9cfd72e01685adb4cd702fe7ea042` (PR #68). Servers only;
the Mac, iPhone and Android apps stay on 61.

WaiClaw, Wolf and Grant now transcribe every recording on our own OpenRamble
server, `https://stt.waiwai.is` (wai-stt, 49.12.110.232), instead of ElevenLabs
(WaiClaw, Wolf) or the bundled whisper.cpp (Grant). Each server's `deploy/.env`
sets `OPENSTRUDEL_STT_URL` and `OPENSTRUDEL_STT_KEY`. Spoken answers stay on
ElevenLabs.

- Deployed with build 61's procedure as image `openstrudel:61-stt-8ea6785`:
  backup, health, Telegram, SQLite integrity and record counts (unchanged), plus
  a check from inside each container that the speech server answers with its key.
  WaiClaw's news timers were stopped for the backup and restored.
- wai-stt: Caddy 2.11.7 with a Let's Encrypt certificate for the name. ufw
  allows 443 only from the three servers, and port 80 for renewals, where Caddy
  only redirects. The OpenRamble service keeps its localhost-only sandbox.
- A 58-second Russian Common Voice recording through each server's
  `/v1/speech/transcribe`: 11.7 s, the same text on all three. An 18-second
  voice note sent from Mik's Telegram to each bot: transcript posted in 12.1 s.
  Before, Grant took 100–230 s per note.
