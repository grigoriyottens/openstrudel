# Build 44: subscriptions and fixes from build 43

Build 44 ships six merged pull requests on top of [build 43](2026-10-15-build-43.md):
- [#35](https://github.com/mikwiseman/openstrudel/pull/35): on iPhone, removing a device closes its sheet.
- [#36](https://github.com/mikwiseman/openstrudel/pull/36): the owner can rename a server whose ChatGPT account is unavailable.
- [#37](https://github.com/mikwiseman/openstrudel/pull/37): every connection link lasts a day.
- [#38](https://github.com/mikwiseman/openstrudel/pull/38): server setup shows its progress on a bar.
- [#39](https://github.com/mikwiseman/openstrudel/pull/39): moving an employee starts on the first click and explains what stopped it.
- [#40](https://github.com/mikwiseman/openstrudel/pull/40): Grok, Kimi Code and GLM Coding Plan subscriptions.

The release is cut from `main` at `e0e8a44`. The build number is 44.

## What changed for users

- **Subscriptions.** Grok signs in inside the unmodified Grok Build, which ships in the app and talks over ACP. Kimi Code and GLM Coding Plan take a key and run in Claude Code. Grok works for the owner only.
- **Links.** Owner and colleague links last 24 hours. Settings lists every waiting link with its role, and any of them can be canceled.
- **Rename.** A server can be renamed by its owner even when its ChatGPT account is unavailable.
- **Moving employees.** A move waits only for the moving employee's own work. When something stops it, the app says what.
- **Setup and iPhone.** Server setup shows a step-by-step progress bar. On iPhone, removing a device closes its sheet.

## Verification

Every scenario ran on the signed, notarized build, before publishing where possible. The full matrix is in `.data/release-44/scenarios.md`.

- **Tests on `main`:** TypeScript passes 498 tests with 2 skipped. The Mac app passes 311 tests.
- **Signed app:** the five packaged-app tests pass. They check the bundled Node, Claude Code with its JIT entitlement, Grok Build with its license and notices, and that no link is dangling.
- **Sparkle:** the archive signature verifies against the public key inside the installed 43 app, which is the check Sparkle makes. The Team ID and the key are unchanged. The DMG holds only the app and the Applications link.
- **Fresh install on Mac:** the shipped runtime started a brand-new Home, and every health flag was present. The shipped app ran on it as an isolated QA copy. Each check below used local mock providers:
  - Kimi Code (`x-api-key`) and GLM (bearer) answered through the bundled Claude Code.
  - xAI answered through Codex.
  - A rejected Kimi Code key showed the replace-key message, and the next turn recovered.
  - Settings → Accounts shows Grok under Subscriptions, and Kimi Code and GLM Coding Plan under API keys.
  - Grok sign-in showed a real x.ai device code and canceled cleanly.
  - With no ChatGPT account, the device was renamed from its context menu.
- **Grok Build:** the bundled binary answers the ACP handshake (protocol 1, sign-in method `grok.com`). It refuses to work before sign-in, and `grok login --device-auth` from the bundle gets a code from accounts.x.ai.
- **Links:** colleague and owner links expire after 24.0 hours and are listed with their roles. A colleague paired and talked to an employee. Canceled and used links were refused.
- **iPhone simulator:** the UI suite ran on a fresh iPhone 17 simulator with iOS 27. Of 24 runnable tests, 21 passed. The other 3 fail the same way on build 43, so none is a regression:
  - The approval-mode step of `testSettingsEmployeesMessagesAndRecovery` depends on timing.
  - A 17×21 pt refresh icon in services is too small to tap comfortably.
  - A store-preview test is out of date.

  Tests that need live servers or real accounts were skipped.
- **Upgrades rehearsed on real data:** copies of this Mac's database and of Server's database ran under the 44 runtime. The sandbox allowed only loopback traffic, so Telegram and providers were unreachable.
  - Server's copy came from 1.0.4, with 7 employees, 8 chats, 5,980 messages and 8 schedules.
  - The Mac mini's copy came from build 40.
  - Integrity held, every count stayed the same, and every timeline loaded.
  - The copies were deleted afterwards.

## Found during release

After Server moved to 44, Rename for Server stayed disabled until the Mac app was relaunched. The app checks owner rights once per connection, and it had checked while Server still ran 1.0.4, which refuses that request. This fix is queued for build 45.

## Known limits

- Grok, Kimi Code and GLM Coding Plan were verified up to sign-in and against mocks. A live turn needs Mik's own accounts.
- No local Docker was available, so a fresh Linux install was not tested on its own. Both real server upgrades rebuilt the Home image on Linux, with automatic rollback.
- The hosting backend change for the 24-hour recovery window (#37) is not deployed.
- WaiPhone was not reachable during the release, so the iOS build is not yet installed on a physical device.
