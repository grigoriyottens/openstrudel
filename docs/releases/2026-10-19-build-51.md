# Build 51 — tools, native memory and three-server recovery

Published 19 October 2026. Mac and Home artifact source:
`94070f6cd1924bafd4171819e6c9e94498784ddc`.
All three running Home images use that source. This release includes the
[speech and Devices improvements from build 50](2026-10-19-build-50.md).

## Changes and findings

- Idle native runtimes accumulated OS threads until sandbox launches failed
  with `EAGAIN` near Docker's 512-task ceiling. Idle contexts now leave the
  runtime cache while active turns, requests, initialization and sign-ins remain.
  Native histories, files and memories survive eviction. The Docker task cap
  was removed; final observed process counts were 139, 193 and 100.
- Native tool failures now produce an incident in the root employee and owner
  diagnostics. A successful subsequent task clears it and records recovery.
  Infrastructure failure followed by silence can recycle the affected runtime;
  uncertain external actions are not automatically replayed.
- Office Scout's plugin had root-owned cached files. Ownership was repaired;
  actual native execution with that plugin succeeded. Linux images now include
  Poppler, and the family assistant read an original PDF through `pdftotext`.
- Forty existing Familia/Baby documents were stored under attachment names while
  schedules referenced their logical paths. They were moved to the correct
  paths; attachment records and source indexes were updated together. Current
  journals and later corrections were retained. Historical agent instructions
  were kept as attachments rather than activated as new workspace instructions.
  A separate backup preserves the exact pre-repair files and database.
- Telegram typing indication refreshes throughout processing and stops when the
  final overlapping request finishes. All three bots accepted the live typing
  action; lifecycle and failure handling were tested separately.
- Removed redundant reply-length, attachment-count, five-minute recording,
  scheduled-prompt, SOUL and plugin-file-count restrictions. The full list and
  retained resource/service constraints are in the
  [memory and limits decision](../architecture/memory-and-limits-2026-10-19.md).

## Memory and original sources

Codex provides native selective memory, compaction and retrieval. The owner's
root employee can search a small catalogue of original workspaces, exact chat
history and native memories for its own server. Source access is read-only;
group and employee scopes retain their existing boundaries.

The native default reserved the last 25% of subscription allowance from memory
generation. The personal/Grant account had 20% remaining and no extraction jobs.
After removing that reserve, native extraction and generated summaries were
observed on all three servers. One snapshot contained 12/12/1 extraction outputs
and 7/11/3 summary files for WaiClaw/Wolf/Grant respectively. Native jobs remain
selective and asynchronous; the audit also observed native retry/error records
during runtime churn. This is not a guarantee of immediate or lossless summaries.
Original documents and full history remain the authoritative sources.

Mem0, Letta, Graphiti and QMD were considered. No second memory service was
installed. Server capacity can be increased if a demonstrated retrieval problem
justifies a ready-made index; RAM alone is not a reason to reject one.
