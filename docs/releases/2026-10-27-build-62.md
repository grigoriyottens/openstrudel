# OpenStrudel 1.0 (62)

Source: `19b8c009323534c6d6118dc1ecaaf6bd1b11ea64` (PR #72). The servers stay on
`openstrudel:61-stt-8ea6785`, because the Home runtime did not change.

## Changes

Build 62 fixes three cloud setup issues from the 19 October code review.

- DigitalOcean setup downloads exactly the Home version it was quoted with. A
  release published during an installation no longer fails all five attempts.
- A stuck DigitalOcean installation can start over after the person confirms
  they deleted the server and DigitalOcean lists no server with its tag. No
  server is created without a fresh price confirmation. A connection whose
  droplet was deleted is no longer added again.
- A failed setup on your own server can be retried after an app update changed
  only the bundled installer. A pending setup can be forgotten on this Mac.
- AgentMetal no longer trusts the first SSH key automatically. The person
  confirms the server fingerprint before anything runs over SSH.
- The release guide keeps the previous build's versioned Home archive until the
  next release, so a cloud installation quoted earlier can still download it.

## Verification

- Runtime setup tests: 100 passed, typecheck clean. Native DigitalOcean, server
  setup, AgentMetal and localization suites: 72 passed.
- The app and DMG are signed, notarized (Accepted), stapled and accepted by
  Gatekeeper. The app inside the DMG has the same code directory hash as the
  staged release. The packaged runtime and installer checks passed (5 tests).
- The Sparkle feed and archive signatures verify. The feed lists 62 first and
  keeps the history from 61 back to 49.
- The release Mac updated through the real Sparkle prompt from 61 to 62 and
  relaunched. Its executable matches the staged release, Gatekeeper accepts it,
  and all three Homes appear. The rollback snapshot is marked healthy.
- WaiWeb: the 61 DMG was removed. Home 61 stays for cloud setups quoted before
  this release, and APK 3 stays because there is no newer APK. `SHA256SUMS`
  lists the remaining files, verified over public HTTPS.
- iOS 62 was uploaded once. Apple reports it VALID, and it is in the internal
  TestFlight group Mik. This is internal TestFlight, not an App Store or
  external beta release.
