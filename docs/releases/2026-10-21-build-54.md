# OpenStrudel 1.0 (54)

Source: `e004c684a0f572bf04cfe0fd2f715234227c5620`.

Native connector failures now create a notice in the main assistant and reach
the paired Telegram owner, including failures inside an otherwise useful answer.
The partial answer is retained. A repeated failure of the same tool does not
create another incident; only a successful call to that tool clears it.

Operational notifications use the existing durable outbox and resume after a
successful Telegram poll. A lost acknowledgement can produce a repeated status
notice. Business messages with an uncertain delivery are never replayed by this
path. No notification service, polling job or agent was added.

Enabled native apps are saved with their existing audience configuration across
account changes. This preserves the user's selection, without copying OAuth
credentials or granting access to other audiences. A provider can still require
sign-in under a different account.

Scheduled editions now follow their saved quiet-run instructions. The generic
schedule prompt no longer contradicts a request to return `NO_REPLY` when there
is nothing to publish.
